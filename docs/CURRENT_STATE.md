# 当前状态

## 一句话结论

S2 V2 已通过修正后的 VectorBT 经济筛选，决策为 **CONTINUE_S2_TO_RQALPHA**。S1 仍为 `REJECT_S1`；S2 V1 在“连续全局行 + 每月精确重平衡”语义下仍是已拒绝的历史版本；S2 V2 采用逐资产最近 200 个有效观测与仅目标变化时提交订单，下一步只做 RQAlpha 权威验证，暂不启动 S3。

## 为什么 V1 被拒绝

V1 的完整样本 CAGR 7.01%、最大回撤 -26.18%、Sharpe 0.726，风险调整表现并不差，但有两个无法接受的证据问题：

- canonical 中 510500.SS 仅缺少 2015-04-13、2015-04-14 两个观测，连续 200 个全局行规则却让它约十个月无法计算均线；2015 年提前降风险因而被数据缺口混杂。
- V1 每月重置精确目标权重，即使趋势状态不变，组合漂移也会触发交易；年均约 11.70 个月实际有订单，共 1,001 个资产级订单。

所以 `REJECT_S2` 是对 V1 证据和执行表达的合理结论，不等于已经证明趋势假设无效。

## V2 审计了什么

资产池、防御资产 `511010.SS`、200 个观测、月末信号、下一观测日执行和 15 bps 单边成本全部冻结，只比较三个版本：

```text
V1  = 连续 200 个全局行 + 每月精确目标重平衡
V2A = 最近 200 个有效观测 + 每月精确目标重平衡
V2B = 最近 200 个有效观测 + 仅目标变化时提交
```

V1→V2A 只隔离数据语义，V2A→V2B 只隔离执行语义。没有搜索均线窗口、增加 no-trade band、波动率配置或其他策略。

正确的可用性定义是：对每个资产独立使用截至信号日最近 200 个非缺失历史价格；信号日自身必须有价格；不足 200 个有效观测或当前缺价均为“不可用”。不得前向填充、置零、合成价格或读取未来数据。

## 510500.SS 缺失数据结论

Tushare 的 SSE 交易日历显示 2015-04-13、2015-04-14 均为开市日；`fund_daily` 两日无记录，`fund_adj` 两日均有复权因子。RQAlpha 官方 bundle 则给出价格 2.243、成交量为 0 的 bar。证据支持标的当日无成交或停牌、两个数据源采用不同表达，但没有公告级证据确认具体原因，因此标记为 **CAUSE_UNRESOLVED**。

V2 没有把 RQAlpha 的携带价格写回 canonical。它只防止两个缺失值污染之后 200 个全局行，并继续把缺失当日的资产判为不可用。

## 月度检查不等于实际操作

V2A 和 V2B 都需要每月末自动或人工检查一次信号。区别在于：

- V2A 年均 11.70 个月实际交易，共 1,019 个资产级订单；
- V2B 年均约 **7.67 个月**实际交易，共 644 个资产级订单；
- V2B 在 161 个可执行检查月中有 58 个月无需操作；
- 实际操作时平均触及约 **6.25 只 ETF**，单月最多 10 只；
- 趋势状态变化与全部目标变化分别统计，可用性变化不冒充趋势变化；

因此真实体验是：每月检查一次，但平均一年约 7–8 个月需要操作，每次通常约 6 只 ETF。它不是极低触达方案，不过比 V1 的机械月月重平衡明显减少工作量，且没有用额外参数换取这一结果。
