# S2 RQAlpha 上游原生执行闭环 V1

## 决策

最终决策为 **ADOPT_UPSTREAM_RQALPHA_EXECUTION**。

采用 PyPI 已发布的 RQAlpha 6.3.x，并为冻结目标回放显式启用原生 `base.partial_fill_on_insufficient_cash`。保留 `order_target_portfolio`，不实现本地成本推导现金预留，也不加入重试或其他执行政策。

## 已知事实与冻结输入

本轮没有重做数据、缺失、可用性、信号时点、V1/V2、滚动区间或成本敏感性研究。这些已关闭事实已迁入 [研究账本](../../docs/RESEARCH_LEDGER.md)。

实验始终读取既有 [S2 V2B 冻结目标](s2_v2_frozen_targets.csv)：103 个执行日，SHA-256 `9cc5a8e70751f274cb7c4f900784400bd8de684450833ba6d4034fd75ca70b61`。回放区间、初始资金、10 bps 费用、5 bps 滑点、current-bar 撮合和 25% 成交量限制均不变；RQAlpha 内不重算信号。

## 官方上游检查

检查日期为 2026-09-11。

- [PyPI](https://pypi.org/project/rqalpha/) 的最新已发布稳定包为 6.3.0（2026-07-23）；
- [官方 6.3.0 changelog](https://github.com/ricequant/rqalpha/blob/release/6.3.0/CHANGELOG.rst)明确新增“资金不足时按配置进行订单部分成交”；
- [官方配置](https://github.com/ricequant/rqalpha/blob/release/6.3.0/rqalpha/config.yml)将 `base.partial_fill_on_insufficient_cash` 默认设为 false，因而本项目必须显式开启；
- [官方撮合实现](https://github.com/ricequant/rqalpha/blob/release/6.3.0/rqalpha/mod/rqalpha_mod_sys_simulation/matcher/base.py)按真实执行价、可用现金、费用、最小数量和步长缩减开仓成交量；关闭开关时仍整单拒绝；
- 旧 `order_target_portfolio` 在 100% 目标下只按估值价预估交易费用；6.3.0 关闭新开关的 B 组仍完整复现 5.6.5，证明版本升级本身没有补足撮合滑点后的现金；
- 6.0.0 新增 [`order_target_portfolio_smart`](https://github.com/ricequant/rqalpha/blob/release/6.3.0/rqalpha/mod/rqalpha_mod_sys_accounts/api/order_target_portfolio.py)，其求解会估计交易成本并约束现金，6.1.4 扩展到 ETF/LOF；但 C 组已经关闭主导问题，继续改 API 会同时引入新的估值和组合求解语义，因此没有运行 D 组；
- 官方仓库另有 2026-09-07 的 [`release/6.4.0` 标签](https://github.com/ricequant/rqalpha/tree/release/6.4.0)（提交 `a5fb4e4`），但尚未发布到 PyPI，且 changelog 要求旧 bundle 增加 `fund_type`。隔离测试结果与 6.3.0 完全一致，当前不采用 Git 标签依赖。

上游已经直接解决当前阻塞，所以没有继续寻找或引入社区依赖。

## 隔离兼容实验

5.6.5 结果作为只读控制；6.3.0 和 6.4.0 各自安装在仓库外隔离环境。完整比较见 [CSV](s2_rqalpha_upstream_comparison.csv)。

| --- | ---: | ---: | ---: | ---: |
| 原生开关 | 关 | 关 | 开 | 开 |
| 现金整单拒绝 | 34 | 34 | 0 | 0 |
| 现金剩余量取消 | 0 | 0 | 32 | 32 |
| 成交量限制状态 | 8 | 8 | 5 | 5 |
| 显著偏离执行日 | 34 | 34 | 5 | 5 |
| 显著偏离检查月 | 72 | 72 | 39 | 39 |
| 现金权重大于 5% 的检查月 | 49 | 49 | 2 | 2 |
| 平均执行日总绝对偏离 | 12.17% | 12.17% | 1.75% | 1.75% |
| 平均现金比例 | 6.22% | 6.22% | 0.46% | 0.46% |
| CAGR | 7.87% | 7.87% | 6.88% | 6.88% |
| 最大回撤 | -22.45% | -22.45% | -25.41% | -25.41% |

6.3.0 在关闭开关时除原生 Sharpe 的极小口径变化外，与 5.6.5 的订单、成交、成本、收益、回撤和目标追踪结果一致，证明升级本身没有改变冻结输入或主要执行语义。

开关开启后，32 个买单按可用现金完成大部分成交并取消剩余量；它们不再是整单拒绝。2013-04-01 的首个 100% 目标不再令组合连续三个月全现金。现金权重大于 5% 的检查月只剩 2013-10 和 2016-05 两个月，均由原生成交量限制导致，不是资金不足整单拒绝持续留空。因此主导的现金驱动持久漂移已关闭。

## 经济与操作含义

实现组合 CAGR 从控制的 7.87% 降至 6.88%，最大回撤从 -22.45% 变为 -25.41%；相对 VectorBT 的 6.56% 和 -26.18% 没有形成实质否定。Sharpe 下降到 0.342，但两个框架使用不同风险自由利率和交易日口径，不单独用差值判定执行失败。

原生记录包含 630 个订单和 630 条成交，交易成本 64,843.53 元，换手 22.90；期末现金 7,600.98 元，平均现金比例 0.46%。平均执行日总绝对偏离为 1.75%，最大值 48.57%。

使用者仍需完成 161 次月度检查；有实际成交的月份从 102 增至全部 103 个目标变化月，年均约 7.68 个。显著偏离执行日仅剩 5 个；材料差异表中的主要直接证据是成交量取消，一个 2014-02 现金剩余量取消与同日未完成卖出共同出现。39 个显著偏离检查月大多是 `SIGNAL_CHANGE_ONLY` 下资产价格自然漂移，现金比例通常接近零，不能再解释为现金失败持续留空。

## 采用内容与保留代码

- 依赖约束更新为 `rqalpha>=6.3,<6.4`，防止未审计的 6.4 自动进入；
- S2 回放显式开启 `partial_fill_on_insufficient_cash`；
- 保留旧 `order_target_portfolio`，不采用 `order_target_portfolio_smart`；
- 通用配置函数改收显式引擎参数，移除对 S1 配置类型的错误耦合；
- 已有 S1 适配器只做 6.x 必需的 `listing_at` → `active_at` API 兼容，并让历史脚本动态记录实际框架版本；不改变已拒绝的 S1 语义或历史报告；
- 本地代码仍只有冻结输入、代码映射、薄回放、原生结果压缩和有界目标追踪。

没有实现现金预留、订单 sizing、撮合、费用、账户、持仓或订单生命周期框架。

仓库仍没有活动的提交状态/工作流门禁；本 Goal 没有增加 CI。若需要，只能由后续独立维护 Goal 添加保护 `pytest`、Ruff 和 Mypy 的最小工作流。
